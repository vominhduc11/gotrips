# CLAUDE.md

Ngữ cảnh đầu vào cho Claude Code khi làm việc trong repo **GoTrips** — nền tảng đặt tour du lịch trực tuyến (MVP). Trả lời và viết comment bằng **tiếng Việt**, trừ khi người dùng yêu cầu khác.

## Tổng quan monorepo

| Thư mục | Vai trò | Công nghệ | Cổng (Docker) |
|---|---|---|---|
| `gotrips-api/` | Backend REST API | Spring Boot 4.1 (Maven), Java 25, JPA, Flyway, PostgreSQL, Spring Security, Actuator, springdoc-openapi | 8080 |
| `gotrips-admin/` | Trang quản trị (SPA) | React 19 + Vite 8 + TypeScript, phục vụ bằng nginx | 8081 → 80 |
| `gotrips-web/` | Website khách hàng | Next.js 16 (App Router) + React 19 + Tailwind CSS 4 + TypeScript | 3000 |
| (gốc) `docker-compose.yml` | PostgreSQL 17 + 3 service trên | | DB 127.0.0.1:5432 |

Tài liệu nghiệp vụ ở gốc repo (`.docx`): `GoTrips_Phan_tich_chuc_nang_va_MVP.docx` (phân tích chức năng & MVP) — đọc khi cần hiểu phạm vi MVP.

### Trạng thái hiện tại
- `gotrips-api`: có **xác thực** (migration `V1__create_users_and_roles.sql`: bảng `users`, `roles`, `user_roles`; `POST /auth/register`, `POST /auth/login`, `GET /auth/me`; JWT HS256 bằng OAuth2 Resource Server) và **dữ liệu danh mục công khai cho website** (migration `V2__create_catalog_and_newsletter.sql`: điểm đến, tour + lịch khởi hành, khách sạn + loại phòng, sân bay + chặng bay, đánh giá, đăng ký ưu đãi; 6 `GET` cho Trang chủ + `GET /tours` (tìm tour: lọc/sắp xếp/phân trang) + `GET /tours/{slug}` (chi tiết tour) + `GET /hotels` (tìm khách sạn theo điểm đến/khoảng ngày/khách/số phòng) + `GET /hotels/{slug}` (chi tiết khách sạn) + `POST /newsletter/subscriptions`, xem mục "gotrips-api"). Còn lại (tìm vé máy bay, booking...) **chưa có** entity/controller; thư viện nền (validation, MapStruct, Testcontainers, CORS, ProblemDetail) đã dùng thật.
- `gotrips-admin`: đã dọn template Vite, cài và cấu hình đủ thư viện; mới có Dashboard tạm và trang 404, chưa gọi API (xem mục "gotrips-admin" bên dưới).
- `gotrips-web`: Trang chủ, tour (`/tours`), **khách sạn** (`/hotels`, `/hotels/[slug]`, `/hotels/[slug]/book`) và **vé máy bay** (`/flights`, `/flights/book`) đã dựng xong; **Trang chủ**, `/destinations`, **tour** (`/tours`, `/tours/[slug]`, phần thông tin tour ở `/tours/[slug]/book`) và **khách sạn** (`/hotels`, `/hotels/[slug]`, phần thông tin khách sạn ở `/hotels/[slug]/book`) lấy dữ liệu từ gotrips-api thật (xem "Trang chủ lấy dữ liệu từ API" bên dưới), còn trang vé và **luồng đặt chỗ** (tạo đơn, `/bookings`) vẫn dùng **dữ liệu mock** (chưa gọi API thật); cả ba dịch vụ đều tìm → xem → đặt được (xem mục "Khách sạn" và "Vé máy bay" bên dưới). `/tours` lọc/sắp xếp/phân trang bằng URL search params (`destination`, `q`, `date`, `guests`, `sort`, `page`; parse bằng `lib/schemas/tour-filters.ts`, **API tính** kết quả qua `GET /tours`, ánh xạ tham số ở `lib/data/tour-request.ts`, cache ở `lib/data/tours.ts`), partial prerender: tiêu đề tĩnh, danh sách stream trong `<Suspense>`. Trang chi tiết `/tours/[slug]` đã có (`generateMetadata`, JSON-LD `TouristTrip`; gồm giới thiệu, lịch khởi hành, đánh giá, thẻ giá; **không có `generateStaticParams`**, xem bullet "Tour" bên dưới). `page.tsx` **không `await params`**: chỉ truyền Promise xuống `TourDetail` bọc trong `<Suspense fallback={<TourDetailSkeleton />}>`, vì App Shell dùng chung cho mọi liên kết tới route nên không được buộc vào một slug (nếu không dev overlay báo "URL data outside of Suspense"; `/hotels/[slug]` và `/hotels/[slug]/book` làm giống hệt qua `HotelDetail` và `BookHotelContent`). Trang `/tours/[slug]/book` làm giống hệt: `page.tsx` chỉ truyền Promise xuống `BookTourContent` (`components/booking/BookTourContent.tsx`) trong `<Suspense>`. **Luồng đặt tour là PROTOTYPE, chưa nối BE/DB** (tạo đơn/chỗ trống vẫn kiểm theo dữ liệu mock):

Trang `/login` và `/register` là form React Hook Form + Zod + Server Action (`lib/actions/auth.ts`):
  - `loginAction` gọi `POST /auth/login`. 401 → "Email hoặc mật khẩu không đúng" (chung cho sai email lẫn sai mật khẩu, API cũng không phân biệt). Thành công → lưu `accessToken` (JWT do API cấp) vào **cookie phiên** `gotrips_session` (httpOnly, `sameSite=lax`, hạn = `expiresIn` của token; token **không** trả về trình duyệt) rồi toast + về `/` (hoặc `?next=` nếu có và an toàn). Email gõ hoa/thừa khoảng trắng vẫn đăng nhập được (API chuẩn hoá).
  - `registerAction` gọi `POST /auth/register` (chỉ gửi `fullName`/`email`/`password`; `confirmPassword`, `acceptTerms` chỉ kiểm ở form). 409 (email đã đăng ký) và 400 đều kèm `errors[]` theo field → `fromApiFieldErrors` (`lib/actions/field-errors.ts`) gắn lại đúng ô. Thành công → `/login` (chưa tự đăng nhập).
  - Lỗi mạng/timeout/5xx → "Hệ thống đang bận…"; log chỉ ghi nguyên nhân, **không** ghi email/mật khẩu/token.
  - Luật mật khẩu (8–72 ký tự, có chữ và số, **tối đa 72 byte** vì BCrypt từ chối quá 72 byte) có ở cả `lib/schemas/auth.ts` lẫn API (`RegisterRequest`): đổi một nơi phải đổi nơi kia.
  - `getCurrentUser` (`lib/auth/session.ts`) đọc cookie rồi gọi `getMe()` (`GET /auth/me`, `cache: "no-store"`), bọc `cache()` của React để Header, lời chào, trang đặt chỗ... trong cùng một lượt render chỉ tốn một request tới API. 401 (hết hạn, sai chữ ký, tài khoản đã xoá, hay cookie cũ của bản demo) → coi như khách; API sập/lỗi 5xx → log rồi coi như khách. **Phải gọi `unstable_rethrow(error)` trước khi nuốt lỗi**, nếu không lượt prerender/prefetch bị Next ngắt giữa chừng ("fetch() rejects when the prerender is complete") sẽ coi người đã đăng nhập là khách. ## Lệnh thường dùng

Chạy toàn bộ stack (cần Docker, file `.env` copy từ `.env.example`):
```bash
docker compose up --build
```

Chạy từng phần khi phát triển (chạy DB bằng `docker compose up gotrips-db` trước):
```bash
# API (từ gotrips-api/) — mặc định nối DB localhost:5432
./mvnw spring-boot:run   # cần biến môi trường GOTRIPS_JWT_SECRET (xem bảng biến môi trường)

./mvnw test              # cần Docker (Testcontainers) + JDK 25 (206 test); máy chưa có JDK 25 thì thêm -Djava.version=24 để chạy thử

# Admin (từ gotrips-admin/)
npm run dev        # vite
npm run build      # tsc -b && vite build
npm run lint

# Web (từ gotrips-web/)
npm run dev
npm run build
npm run lint

# Web + admin
npm test           # vitest run (web: 398 test đơn vị; test:watch để chạy chế độ theo dõi)
npm run api:gen    # orval: sinh client/type từ http://localhost:8080/v3/api-docs (API phải đang chạy)

# Chỉ web
npm run test:e2e   # playwright (thư mục e2e/): tự build rồi chạy next start trên cổng 3100.
                   # CẦN gotrips-api + DB đang chạy (docker compose up -d gotrips-db gotrips-api): các spec đăng nhập
                   # tạo tài khoản thật qua API (e2e/fixtures.ts), và dữ liệu Trang chủ lấy từ API đã có seed (profile `seed`,
                   # compose bật sẵn). Web gọi API ở API_URL (mặc định http://localhost:8080). Chỉ lúc BUILD là không cần API.
```

## Quy tắc dùng thư viện (BẮT BUỘC, áp dụng cho cả 3 dự án)

Mục tiêu: session nào cũng dùng đúng thư viện đã chốt, **không "code chay"** lại thứ thư viện đã làm được, và cũng **không dùng thư viện sai chỗ**.

1. **Đọc manifest trước khi viết code.** Mở `package.json` (web, admin) hoặc `pom.xml` (api) của dự án đang sửa và đối chiếu với các bảng bên dưới.
2. **Thư viện đã cài thì bắt buộc dùng.** Không tự viết lại chức năng mà thư viện đã cài cung cấp: quản lý form, validation, fetch/cache phía client, component UI, icon, toast, xử lý ngày, bảng dữ liệu, map DTO, test.
3. **Thư viện có trong bảng nhưng chưa cài:** không viết tạm bằng code tay, cũng không tự chọn thư viện khác thay thế. Dừng lại, báo người dùng và đề xuất lệnh cài đúng thư viện trong bảng.
4. **Thư viện ngoài bảng:** không tự thêm. Phải hỏi người dùng trước. Khi được duyệt thì cập nhật bảng trong file này cùng lúc với việc cài.
5. **Đúng phạm vi.** "Dùng triệt để" nghĩa là dùng thư viện cho đúng việc ghi ở cột "Dùng cho". Không đưa thư viện vào những chỗ ghi ở cột "Không dùng cho".
6. **Code viết tay có từ trước** (SVG icon tự vẽ, Button tự viết, form validate bằng `useState`…): không viết thêm code mới theo kiểu cũ. Khi sửa vào file đó thì chuyển nó sang thư viện tương ứng.
7. **Dùng API theo đúng phiên bản đã cài, không theo trí nhớ.** Nhiều thư viện vừa có bản lớn mới: Next 16, React Router 8, Zod 4, TanStack Table 9, Tailwind 4, Spring Boot 4, Testcontainers 2. Hãy đọc docs đi kèm package hoặc docs chính thức của đúng phiên bản.

## gotrips-api (Spring Boot)

- Package gốc: `com.gotrips.gotrips_api` (lưu ý dấu gạch dưới). Cấu hình ở `src/main/resources/application.yaml`.
- **Schema do Flyway quản lý**, Hibernate chỉ `ddl-auto: validate` → mọi thay đổi bảng phải là file migration mới trong `src/main/resources/db/migration` (`V1__...`, `V2__...sql`), không sửa migration đã áp dụng. Chỉ dùng kiểu cột `integer/bigint/numeric/varchar/boolean/date/time/timestamptz/text` (và `text[]`, map bằng `@JdbcTypeCode(SqlTypes.ARRAY) List<String>`, đã kiểm với Hibernate 7.4): Hibernate so kiểu cột nghiêm ngặt khi `validate` (`smallint` không khớp `Integer`, `numeric(2,1)` cần `BigDecimal`). **Dữ liệu mẫu** nằm ngoài migration: `src/main/resources/db/seed/R__seed_catalog.sql` (migration lặp lại của Flyway), chỉ được nạp khi bật profile `seed` (`application-seed.yaml` thêm `classpath:db/seed` vào `spring.flyway.locations`); idempotent (`ON CONFLICT DO NOTHING` + `setval` cho sequence IDENTITY, vì id được chèn tường minh); muốn nạp lại seed đã sửa thì `docker compose down -v`. Seed chép từ `gotrips-web/lib/mock/*` (cùng id/slug/giá/ngày/ảnh) và có trong jar nhưng không chạy nếu không bật profile.
- `open-in-view: false` → không lazy-load ngoài transaction; map sang DTO trong service.
- Bảo mật (`config/SecurityConfig.java`): stateless, CSRF tắt, xác thực bằng **JWT Bearer** (OAuth2 Resource Server; không còn HTTP Basic). Công khai: `/actuator/health/**`, `/v3/api-docs/**`, `/swagger-ui/**` (để Orval đọc spec), `POST /auth/register`, `POST /auth/login`, và dữ liệu cho website: `GET /destinations`, `/airports`, `/tours` (tìm), `/tours/*` (chi tiết `/tours/{slug}`, gồm cả `/tours/featured`; `*` chỉ khớp MỘT đoạn nên `/tours/{slug}/gì-đó` vẫn cần token), `/hotels` (tìm), `/hotels/*` (chi tiết `/hotels/{slug}`, gồm cả `/hotels/featured`; `/hotels/{slug}/gì-đó` vẫn cần token), `/flight-routes/popular`, `/testimonials`, `POST /newsletter/subscriptions`; còn lại cần token. Khi thêm endpoint công khai cho website phải mở rõ ràng **từng đường dẫn** trong cấu hình này (không dùng `/tours/**`, `/hotels/**`: các endpoint chi tiết/đặt chỗ sau này không được vô tình thành công khai; có test `PublicEndpointsTests` canh điều này). Đã có bean CORS (`gotrips.cors.allowed-origins`) cho admin; web gọi từ server nên không cần CORS.
- **Xác thực** (package `auth/`, `user/`): bảng `users` (UUID, email luôn chữ thường — có `CHECK`, `password_hash`, `full_name`), `roles` (CUSTOMER/STAFF/ADMIN, seed ở V1), `user_roles`. Đăng ký công khai luôn là CUSTOMER (request không có trường vai trò). Mật khẩu băm bằng `DelegatingPasswordEncoder` (bcrypt, lưu dạng `{bcrypt}...`). `AuthService.login` luôn chạy một lần so khớp mật khẩu kể cả khi email không tồn tại (không lộ email nào đã đăng ký qua thời gian phản hồi) và trả cùng một thông báo cho sai email/sai mật khẩu. Email trùng → 409 kèm `errors[{field:"email"}]` (kiểm trước + ràng buộc UNIQUE của DB là chốt chặn khi hai request đồng thời).
- **JWT** (`config/JwtConfig`, `JwtProperties`, `auth/JwtService`): HS256 bằng Nimbus, claim `sub` = id người dùng, `roles` = ["CUSTOMER"] (→ authority `ROLE_CUSTOMER`), `iss` = `gotrips-api` (decoder kiểm issuer + hạn). Token chỉ chứa thứ cần để phân quyền; email/tên lấy từ `GET /auth/me`. Chưa có refresh token/thu hồi. Mật khẩu tối đa **72 byte** (annotation `@MaxUtf8Bytes` ở `common/validation`): BCrypt ném `IllegalArgumentException` (→ 500) nếu vượt, mà `@Size` chỉ đếm ký tự nên không đủ cho chữ có dấu.
- **Danh mục công khai cho website** (package `destination/`, `tour/`, `hotel/`, `flight/`, `testimonial/`, `newsletter/`; Controller → Service → Repository; service đọc `@Transactional(readOnly = true)`; không N+1: `join fetch`/một query gom theo danh sách id). Entity danh mục **chỉ để đọc** và chỉ map cột website cần (tour đã map `short_description`; khách sạn đã map mô tả, giờ nhận/trả phòng (`LocalTime`) và tiện ích `text[]` bằng `@JdbcTypeCode(SqlTypes.ARRAY) List<String>` — Hibernate 7 qua được `ddl-auto: validate`; loại phòng map đủ tên/sức chứa/giường/diện tích). Luật nghiệp vụ ban đầu chép từ hàm web cũ; với tour và khách sạn thì API nay là **nguồn duy nhất** (web đã bỏ bản tính của mình):
  - Tour/khách sạn `HIDDEN` không được trả hay đếm ở bất kỳ API nào (cả đánh giá của tour HIDDEN).
  - `/tours/featured` (mặc định `limit` 8): tour ACTIVE + `is_featured` còn ít nhất một chuyến đặt được (`departure_date > hôm nay` và còn chỗ), theo id, `limit` áp dụng SAU khi bỏ tour hết chuyến. Các trường suy ra tính ở `tour/TourCardCalculator` (hàm thuần, có test): giá từ = chuyến đặt được rẻ nhất (hoà giá → chuyến sớm hơn) kèm giá gốc/% giảm của CHÍNH chuyến đó; ngày gần nhất + số chỗ còn lại = chuyến đặt được sớm nhất; `isAlmostFull` = còn ≤ 5 chỗ.
  - `GET /tours` (tìm tour; `TourService.search` + `TourSearchCalculator`, hàm thuần có test): query `destination` (slug), `q`, `date` (`YYYY-MM-DD`), `guests` (1–50), `sort` (`FEATURED` mặc định, `NEAREST_DEPARTURE`, `PRICE_ASC`, `PRICE_DESC`, `RATING`), `page` (≥ 1); **8 tour/trang cố định** (`PAGE_SIZE`). Trả `{ items: TourCardResponse[], total, page, pageCount, destinationName }`. Luật: chỉ tour ACTIVE; slug điểm đến không tồn tại → kết quả rỗng (không bỏ qua bộ lọc), `destinationName` null; `q` so khớp không phân biệt dấu/hoa thường (kể cả `đ → d`) trên "tên tour + tên điểm đến"; `date`/`guests` chọn các CHUYẾN còn đặt được thoả điều kiện và thẻ hiển thị giá/ngày của đúng các chuyến đó, tour không có chuyến nào thoả thì bị loại; không lọc ngày/khách thì tour hết chỗ vẫn hiện (không có giá) và **mọi kiểu sắp xếp đều xếp tour không có giá xuống cuối**, hoà thì theo id (trang 1/2 không trùng hay sót); `page` vượt quá được kẹp về trang cuối (kẹp TRƯỚC khi nhân để không tràn int), `pageCount` tối thiểu 1. **Lọc/sắp/phân trang làm trong bộ nhớ** (đủ cho catalog cỡ MVP: một query tour + một query chuyến đặt được cho cả danh sách); khi catalog lớn phải đẩy xuống SQL.
  - `GET /tours/{slug}` (`TourService.detail`): thẻ tour + `shortDescription` + `departures` (mọi chuyến sau hôm nay, **kể cả chuyến đã đầy**, theo ngày; `isSoldOut`, `isAlmostFull`, giá gốc/% giảm từng chuyến) + `testimonials` của chính tour. Slug không có hoặc tour HIDDEN → **404 như nhau** (`ResourceNotFoundException` → `GlobalExceptionHandler`, `ProblemDetail`), không lộ tour đang ẩn. Phẳng (không lồng thẻ): `TourMapper` (MapStruct) dựng `TourDetailResponse` từ `TourCardResponse` nên thêm trường ở thẻ mà quên ở chi tiết là lỗi lúc biên dịch; các `@Schema` của hai record phải giữ giống nhau. Truy vấn đánh giá nằm ở `TourRepository` (constructor expression, tham chiếu `Testimonial` bằng tên entity) để package `tour` không phụ thuộc `testimonial` (tránh vòng).
  - `GET /hotels` (tìm khách sạn; `HotelService.search` + `HotelStayCalculator`, hàm thuần có test): query `destination` (slug, bắt buộc, ≤100 ký tự), `checkIn`/`checkOut` (`YYYY-MM-DD`, bắt buộc), `guests` (1–30, mặc định 2), `rooms` (1–10, mặc định 1). Trả `{ destinationName, items: HotelSearchResultResponse[] }` (thẻ + `room` + `nights` + `rooms` + `totalPrice`). Luật chép nguyên văn từ web cũ: chỉ khách sạn ACTIVE của điểm đến; mỗi khách sạn lấy loại phòng **rẻ nhất còn chứa đủ khách** (`rooms ≤ guests ≤ maxGuests × rooms`), không có phòng nào vừa thì bỏ khách sạn; `minPricePerNight` ("giá từ" của thẻ) tính trên MỌI phòng chứ không chỉ phòng vừa; `totalPrice = giá × số đêm × số phòng`; sắp `totalPrice` ↑ → `rating` ↓ → id; không phân trang; slug điểm đến không tồn tại → rỗng, `destinationName` null. Sai luật (`checkIn` < hôm nay theo `Clock`, `checkOut` ≤ `checkIn`, > 30 đêm, `rooms > guests`) → `InvalidRequestException` (400, `errors[{field,message}]`, **cùng câu chữ** với `checkStayDates` ở web: đổi một nơi phải đổi nơi kia); thiếu tham số bắt buộc cũng 400 (`MissingServletRequestParameterException`).
  - `GET /hotels/{slug}` (`HotelService.detail`): thẻ + `description`, `amenities`, `checkInTime`/`checkOutTime` (**String "HH:mm"**, mapper định dạng vì Jackson mặc định ra "14:00:00") + `roomTypes` (giá ↑ rồi id). Slug không có, HIDDEN hoặc chưa có loại phòng → **404 như nhau**. Phẳng như tour: `HotelMapper` dựng `HotelDetailResponse`/`HotelSearchResultResponse` từ `HotelCardResponse` bằng `@Mapping(target = ".", source = "card")`; `HotelSearchResultResponse` còn phải chỉ rõ `id`/`name` lấy từ thẻ vì `room` cũng có hai trường đó (không thì MapStruct báo mơ hồ).
  - **`/hotels/featured` và `/tours/featured` trả 200 kèm mảng**, nên `GET /hotels/featured` không bao giờ rơi vào `/hotels/{slug}` (literal thắng) nhưng một khách sạn/tour mang slug `featured` sẽ không truy cập được; web chặn slug này (`isValidHotelSlug`/`isValidTourSlug`).
  - `/hotels/featured` (mặc định 4; web cũng dùng với `limit=50` làm danh sách gợi ý của `/hotels`): ACTIVE và có ≥1 loại phòng, sắp `rating` giảm dần → `review_count` giảm dần → id; `minPricePerNight` = giá một đêm thấp nhất. `/flight-routes/popular` (mặc định 6): theo `sort_order`, kèm sân bay hai đầu. `/airports`: theo `sort_order`. `/destinations`: theo id, `tourCount` chỉ đếm tour ACTIVE (không cần còn chuyến). `/testimonials`: theo id, kèm `tourTitle`.
  - `limit` validate bằng annotation `@ResultLimit` (1–50, `common/validation`); sai → 400 `ProblemDetail` kèm `errors[{field:"limit"}]` (`GlobalExceptionHandler` xử lý thêm `HandlerMethodValidationException` và `MethodArgumentTypeMismatchException`).
  - "Hôm nay" lấy từ bean `Clock` (`config/ClockConfig`, múi giờ `Asia/Ho_Chi_Minh`, `ClockConfig.BUSINESS_ZONE`), tính một lần mỗi request; không gọi `LocalDate.now()` trần. Test ghi đè bằng `Clock` cố định (25/11/2026) trong `TestcontainersConfiguration`.
  - **Newsletter** (`POST /newsletter/subscriptions` → 204): email strip + chữ thường (compact constructor), `@Pattern` cùng regex với `newsletterSchema` của web (không dùng `@Email` vì chấp nhận `a@b`); lưu bằng native `INSERT … ON CONFLICT (email) DO NOTHING` nên email đã có vẫn 204 (không lộ email nào đã đăng ký, không lỗi khi hai request đồng thời). Chưa có rate limit, chưa có luồng huỷ đăng ký.
- OpenAPI/Orval: controller chỉ khai báo kết quả **thành công** (lỗi mô tả trong `description` và trả theo `ProblemDetail`), vì mutator `customFetch` của web ném `ApiError` cho mọi mã lỗi — nhờ đó kiểu client sinh ra gọn (`{ data, status }`, không phải thu hẹp union). Response DTO đánh dấu `requiredMode = REQUIRED` để Orval không sinh field `?`; field có thể null khai `requiredMode = REQUIRED, nullable = true` để ra `T | null`. ### Cài / thêm shadcn trên Windows (các lỗi đã gặp)
- Windows không phân biệt hoa/thường: tên file trong `components/ui/` phải chữ thường (`button.tsx`). Nếu từng có `Button.tsx`, git index (`core.ignorecase=true`) sẽ giữ tên cũ — kiểm tra `git ls-files components/ui` trước khi commit.
- `shadcn add` sinh `import { cn } from "cn"` (npm package `cn`, không dùng). Sau mỗi lần add phải sửa thành `@/lib/cn`, và không cài package `cn`.
- `shadcn add` các component phụ thuộc `button` sẽ hỏi ghi đè `button.tsx`/`badge.tsx` (đã tuỳ biến theo GoTrips). Sao lưu trước, hoặc trả lời "không"; nếu dùng `-o` thì khôi phục lại hai file này.
- `button.tsx` chỉ có size `sm|md|lg|icon|icon-sm|icon-lg` và variant `primary|accent|outline|ghost`. Component shadcn dùng `size="default"` hay variant khác (`secondary`, `destructive`, `link`) sẽ lỗi tsc: đổi sang giá trị có sẵn hoặc thêm vào `button.tsx` cho đúng token.
- `next-themes` không dùng (chỉ chế độ sáng): `sonner.tsx` cố định `theme="light"`.
- Vitest 5 (rolldown) trên Windows có thể báo "Cannot find native binding": chạy `npm install @rolldown/binding-win32-x64-msvc --no-save` (lỗi optional-deps của npm, không ghi vào package.json).
Alias import: `@/*` → thư mục gốc `gotrips-web/`.

### Quy tắc kiến trúc dữ liệu
- Component **không** import `lib/mock/*`; chỉ import `lib/data/*`. Khi chuyển sang API thật, chỉ đổi *thân hàm* trong `lib/data/*` thành `fetch(...)` và map sang kiểu trong `lib/types.ts`; giữ nguyên chữ ký và các directive `"use cache"` / `cacheLife` / `cacheTag`.
- **Hàm data gọi API** (Trang chủ, `/destinations`, tour, khách sạn) vừa phải `"use cache"` vừa **không được chạy lúc `next build`** (build không có API): gọi chúng qua `loadSection` (có `await io()`) từ component bọc `<Suspense>`, xem "Trang chủ lấy dữ liệu từ API". `await params`/`searchParams` hoặc `connection()` ở trang cũng đưa phần đó ra khỏi build (`/tours`, `/hotels`, `/flights`), nhưng **không nên chỉ dựa vào đó** (`partialPrefetching` có thể prerender tiếp): vẫn gọi qua `loadSection`.
- Vì `cacheComponents` bật và logic "ngày còn chỗ" phụ thuộc thời điểm hiện tại, các hàm data phải nằm trong phạm vi `"use cache"` để trang prerender được thành static shell. Dùng `getTodayInVietnam()` (`lib/data/tour-view.ts`), không dùng `new Date()` rải rác. **Client Component cũng không được đọc "hôm nay" lúc render** (client component vẫn prerender trên server, build sẽ lỗi): chỉ tính trong panel lịch (chỉ render khi mở Popover) hoặc trong hàm validate/submit, như `DatePickers.tsx` và `createHotelSearchSchema()`. E2E Trang chủ phải đợi hydrate xong (`gotoHome` trong `e2e/home.spec.ts`), nếu không bấm "Tìm" sớm sẽ submit form kiểu HTML thuần.
- Dữ liệu "View" (tourCount, giá thấp nhất, ngày khởi hành gần nhất...) được **tính** trong `lib/data/*` (phần còn mock: vé) hoặc **do API tính sẵn** (Trang chủ, tour, khách sạn), không lưu trong mock/DB. Tour và khách sạn trạng thái `HIDDEN` không được hiển thị/đếm; khách sạn không có loại phòng nào cũng không hiện (không có "giá từ").
- Sau này admin đổi tour/lịch khởi hành → gọi `revalidateTag("tours")` (các tag đang dùng: `site`, `destinations`, `tours`, `hotels`, `flight-routes`, `flights`, `airports`; `getFeaturedHotels` gắn thêm `destinations` vì thẻ hiện tên điểm đến, `getPopularFlightRoutes` gắn `airports` vì thẻ hiện tên sân bay/thành phố).

### Giao diện / design tokens
- Nguồn duy nhất của màu, bo góc, đổ bóng, font là khối `@theme` trong `app/globals.css`. Bảng màu mặc định của Tailwind **đã bị xoá** (`--color-*: initial`) → chỉ dùng token: `primary-*` (teal), `accent-*` (cam, cho giá/CTA), `neutral-*`, `danger/success`, alias `surface`, `ink`, `ink-muted`, `line`; `rounded-control|card|pill`; `shadow-card|card-hover|search|header`. **Không hard-code mã màu.**
- Chỉ có chế độ sáng. Chữ trắng chỉ đặt trên `primary-700+` / `accent-700+` để đạt tương phản AA.
- Font: Be Vietnam Pro (subset `vietnamese` + `latin`, khai báo weight).
- `cn()` (`lib/cn.ts`) = `clsx` + `tailwind-merge` (`extendTailwindMerge`): gộp class xung đột, class sau thắng. Đã khai báo token riêng `rounded-control|card|pill`, `shadow-card|card-hover|search|header`, `max-w-page`. **Thêm token mới vào `@theme` thì phải khai báo thêm ở `lib/cn.ts`**, nếu không không gộp được (có test ở `lib/cn.test.ts`).
- **Khi dùng shadcn:** biến `--accent` của shadcn là **nền khi hover** (được gán sang `primary-50`). Nó khác với dải màu cam `accent-*` của GoTrips dùng cho giá và CTA. Cần màu cam thì dùng `accent-700`; không dùng `bg-accent` với ý là màu cam.
- Accessibility: giữ skip-link "Bỏ qua điều hướng", `id="noi-dung-chinh"`, focus ring theo token `focus`.
- **Ảnh hiện tại là ảnh mock Unsplash** (placeholder, không phải ảnh thật của địa danh) — phải thay bằng ảnh thật/có bản quyền trước khi ra mắt (`lib/mock/images.ts`).

## Docker
- Cả 3 Dockerfile là multi-stage trên `node:24-alpine` (web, admin) và build Maven (api). Web chạy non-root.
- Thứ tự khởi động: `gotrips-db` (healthy) → `gotrips-api` (healthy) → `gotrips-admin` & `gotrips-web`. Thứ tự này chỉ áp dụng cho lúc CHẠY: `docker compose up --build` build mọi image trước khi khởi động container nên API chưa chạy lúc build web — vì vậy web không được gọi API lúc `next build` (xem "Trang chủ lấy dữ liệu từ API"; Dockerfile web không cần `ARG API_URL`).
- `gotrips-api` chạy với `SPRING_PROFILES_ACTIVE=seed` mặc định trong compose (dữ liệu mẫu danh mục để Trang chủ có nội dung); môi trường thật đặt rỗng.
- Cổng DB chỉ bind `127.0.0.1:5432` để chạy API bằng IDE/mvnw, không lộ ra mạng ngoài.
